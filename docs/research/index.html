VideoJev · MJev-Spatial · Jeva의 논문 본문·부록과 고정된 공개 코드에서 추적한 동작을 구분한다. 이름이 비슷해도 TypeSafe API의 추가 기능이나 서로 호환되는 모델은 아니다.

01. VideoJev

프레임 쌍의 시간 후보 또는 텍스트 선택지를 공유 cosine head로 점수화한다. 시간 구간은 nonempty maximum-sum range로 결정하므로, 구간 반환만으로 사건의 존재를 입증할 수 없다.

  1. 코드 경로: video sampling → native preprocessing → vision features → causal language forward → cosine scores → interval / option decoding.
  2. 캐시 구분: 공개 predict_video/predict_features는 Joint 및 vision-feature reuse다. 언어 forward는 use_cache=False이며, 논문의 prefix caching은 별도 연구 구현을 확인해야 한다.
  3. 재현 경계: 공개 custom training 설정과 논문 설정, 품질 측정과 속도 측정의 context·시간 범위가 다르다. 논문의 speedup을 전체 파이프라인 속도로 옮기지 않는다.

02. MJev-Spatial

기존 attention Q/K로 후보를 비교한다. 수치와 좌표는 coarse-to-fine 분류로 좁혀 간다. 한 단계가 한 forward라는 뜻이지, 전체 좌표 요청이 한 번의 forward라는 뜻은 아니다.

  1. 코드 경로: image processor → native Q/K scoring → task controller → 원본 이미지 crop / 수치 codebook → decode.
  2. 출력 계약: meter·count·degree 단위를 혼합하지 않는다. 단일 point는 원본 이미지의 정규화 [x,y]다. 좌표가 화면 클릭이나 로봇 동작 권한은 아니다.
  3. 실행 전 차단: 선언된 dependency 범위 충돌, 중복 output directory 생성, 없는 inference export가 확인됐다. 공개 체크포인트와 논문 최종 결과의 대응도 확인이 필요하다.

공개 체크포인트 metadata의 불일치만으로 논문 결과 오염을 단정하지 않는다. 정확한 revision·출처 설명·독립 holdout 평가가 필요하다.

03. Jeva

요청과 후보를 각각 인코딩하고, 고정된 option memory를 읽어 요청 상태만 갱신한다. 후보 사이의 경쟁과 후보 집합 안에 답이 있는지를 분리한다.

  1. 코드 경로: request / option encoders → K/V option memory → decision stack → coverage / competition → typed result.
  2. null의 의미: q는 후보 내 조건부 확률, joint mass는 coverage를 곱한 값이다. null은 후보 부재이며 단순한 불확실성이나 검토 요청과 같지 않다.
  3. 검증 경계: 공개 평가 summary는 논문·가이드의 모든 permutation 지표를 내지 않는다. 원 논문의 auxiliary loss·curriculum과 공개 fine-tuning loop도 구분한다.

모델을 돌리기 전에, 계약부터 검사한다

저장소에서 Python 3.10+로 실행한다. 아래 도구는 네트워크·모델·credential을 사용하지 않으며, 입력 안의 미디어 경로도 열지 않는다.

python3 plugins/jev/skills/jev-decisions/scripts/research_kit.py plan --task video-grounding
python3 plugins/jev/skills/jev-decisions/scripts/research_kit.py plan --task spatial-point
python3 plugins/jev/skills/jev-decisions/scripts/research_kit.py plan --task text-choice
python3 examples/research_demo.py

VALID_CONTRACT_ONLY는 요청 형태가 허용된 제한 계약에 맞는다는 뜻이다. 실제 영상의 유효성, 모델 가동 여부, 정확도나 운영 안전을 뜻하지 않는다.

사용자 로컬 /jev에 이 reference를 연결했다면 같은 자연어 요청을 사용할 수 있다. 공개 플러그인 호출은 위 namespace를 따른다. 새 모델 실행 명령이 자동 등록되는 것은 아니다.

근거를 유지하는 갱신 절차

paper revision → code SHA → 실제 진입점·스키마 → 코드/가중치 license → 합성 계약 검사 → 별도 승인된 runtime smoke → 독립 품질 평가 순서로 갱신한다. 논문·코드·문서가 다르면 그 차이를 숨기지 않는다.

공개 reference에는 공개 자료와 직접 작성한 설명만 포함한다. 내부 데이터, 고객 자료, 개인 대화, 비밀키, 모델 가중치와 타 프로젝트 구현은 배포하지 않는다.

Independent community toolkit. 논문·모델·저장소 이름은 각 소유자에게 귀속된다. TypeSafe 또는 연구 저자의 공식 통합이 아니다.
