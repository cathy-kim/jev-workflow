01 / WHAT JEV DOES

기본 아키텍처와 책임 경계

Jev는 state와 질문을 함께 받아 질문별 타입 답변을 반환한다. 자유 형식 설명, 코드 생성, 웹 크롤링, DB 실행은 담당하지 않는다. 넓은 질문을 원자 판단으로 쪼개고 결과의 조합은 코드에 둔다. [S1–S3]

담당해야 하는 일맡기지 않을 일
Jev의미적 관련성·분류·등급 판정최종 권한 승인, 자의적 도구 실행
일반 코드파싱/검증, 정책, 임계값, 재시도, 감사모델 확률을 정확성 보증으로 해석
생성형 LLM설명·요약·SQL·계획 작성생성한 설명을 Jev의 실제 사고 과정으로 표시
사람고위험·불확실·신규 케이스 검토근거 부재를 자동으로 부정 판정
권한 경계
높은 확신은 권한을 만들어 주지 않는다. 인증·허용 목록·결제 승인·개인정보 동의는 모델과 독립적인 코드 관문이다.

02 / PRIMITIVES

Noul · Choice · Score 읽는 법

타입입력 설계답변 해석
Noul참/거짓 명제 1개. 필요하면 true/false 기준 추가.noul=P(true), 0~1. 별도의 confidence 필드 없음.
Choice순서 없는 선택지 맵. 선택지 설명을 서로 구분.최고 확률의 choice + 전체 probabilities + confidence. 최대 255개 선택지.
Score낮은→높은 순서의 criteria 배열, 2~10개 레벨.레벨 인덱스의 확률 가중 평균. 0~(레벨 수−1). 정수가 아닐 수 있음.

세 타입 모두 “설명 생성”이 아니다. 다중 라벨 분류라면 하나의 Choice에 여러 정답을 강요하지 말고, 라벨별 Noul을 독립 질문으로 구성한다. [S4–S6]

Score와 confidence를 혼동하지 않기

# 공식 Score 문서 예제 분포를 재계산 (실제 API 호출 결과 아님)
P(level=0,1,2) = [0.00, 0.57, 0.43]
score = 0*0.00 + 1*0.57 + 2*0.43 = 1.43
normalized_score = 1.43 / (3-1) = 0.715

# Choice, 3개 선택지, 최고 확률 0.90인 설명용 계산
confidence = (p_max - 1/n) / (1 - 1/n) = 0.85
confidence는 정답률이 아니다
Choice confidence는 최대 확률을 균등 분포 기준으로 변환한 값이다. Score confidence는 레벨 간 거리도 반영한다. confidence=0.85를 “정답률 85%”라고 표시하면 안 된다. [S6]

질문 설계 체크리스트

  • 한 질문에 의미 판단 하나만 넣는다. 품질·안전·완료 여부를 섞지 않는다.
  • Choice의 other/unknown은 유용하지만 만능이 아니다. “어느 선택지도 적합한가?”라는 별도 Noul도 평가한다.
  • 같은 요청의 질문은 서로의 답을 보지 못한다. 앞선 답에 의존하는 질문은 다음 요청으로 보낸다.
  • Score의 각 레벨은 관찰 가능한 차이로 정의한다. ID 이름만으로 모델에 설명했다고 가정하지 않는다.
  • 높을수록 위험한 점수와 높을수록 좋은 점수는 방향을 맞춘 뒤 결합한다. 평균으로 치명적 위반을 상쇄하지 않는다.

03 / REQUEST AND RESPONSE

데이터·API 계약

TypeSafe 직접 호출의 기본 경로는 POST https://api.typesafe.ai/v1/systemone이다. 인증은 서버의 Bearer 토큰으로 처리하며 브라우저 번들·문서·로그에 키를 넣지 않는다. [S2]

필드의미구현상 주의
model별칭 또는 버전 모델 ID평가 완료 버전을 고정. 응답 model도 기록.
state문자열 / 객체 / 배열모든 질문이 공유하는 근거. 최소화·익명화·길이 제한.
questions질문 ID → 질문 객체type, instructions, criteria. ID는 결과 연결용.
answers질문 ID → 타입 답변요청한 모든 ID의 존재·타입·범위·유한값 검사.
usage입출력 토큰실제 과금 토큰 기준으로 비용 기록. 공급자별 추가 필드는 별도.

권장 evidence 객체 — 애플리케이션 내부 형식

{
  "record_id": "ticket-example-001",
  "evidence": [{
    "source_id": "ticket-body",
    "source_version": "revision-1",
    "excerpt": "구독 요금이 두 번 청구되었습니다.",
    "content_type": "text/plain",
    "extraction_status": "complete"

위 필드는 TypeSafe 예약 스키마가 아니라 권장 내부 계약이다. 상세 URL·개인 식별자는 로컬 권한 저장소에 두고 모델에는 판정에 필요한 발췌와 익명 ID만 보낼 수 있다.

컨텍스트 한도는 두 개다
TypeSafe 기본값은 요청당 64k, 질문당 32k tokens. state+모든 질문과 state+개별 질문이 각각 한도 안에 있어야 한다. Long Context 헤더로 두 한도를 262k로 높일 수 있지만 공식 문서는 속도·정확도 저하를 경고한다. 문자 수와 토큰 수는 같지 않다. [S3]
최신 버전 ≠ latest 별칭
조회 시 공식 모델표는 1.14를 최신 릴리스로 소개하지만 jev-latest → jev-1.13.0, jev-preview → jev-1.14.0로 기재한다. 운영은 별칭보다 검증한 버전 ID를 사용한다. [S3]

06 / RETRIEVAL-AUGMENTED GENERATION

RAG: 검색과 생성 사이의 검토층

검색기는 후보를 찾고 Jev는 후보의 의미적 유용성을 판단한다. Jev는 검색 후보 밖의 문서를 발견하지 못한다. 문단 관련성과 “답할 만큼 충분한가”는 별도 기준이다.

단계검증할 것
검색Top-K recall, 테넌트/사용자 접근권한, 최신성, 중복 제거
문단 판정질문과의 직접 관련성, 필요한 사실 포함, 잘린 문맥 여부
충분성여러 질문 요소에 대한 coverage, 상충 근거, 날짜·단위 일치
생성 후인용 문단이 실제 주장을 지지하는지, 추가된 무근거 주장 여부
프롬프트 인젝션은 별도 보안 문제
검색 문서의 명령문을 실행 지침으로 신뢰하지 않는다. Jev의 인젝션 분류는 보조 신호일 뿐이다. 도구 allowlist·권한 검사·외부 전송 정책은 독립 관문으로 유지한다.

07 / EVALUATION AND OBSERVABILITY

에이전트 평가: JevEval과 Opik

JevEval은 Jev 답변을 코드로 결합하는 DeepEval의 지표다. Opik은 trace·데이터셋·실험 결과를 저장·비교하는 관측 플랫폼이다. 둘을 함께 쓸 수 있지만 둘 다 Jev 모델 자체는 아니다.

JevEval 동작정확한 의미
일반 모드Noul은 P(true), Score는 기대 레벨을 0~1로 정규화, Choice는 적용되는 선택지의 credit 가중 확률. 그 뒤 질문별 가중 평균.
N/A Choicecredit=None인 선택지 확률 합이 0.5 이상이면 해당 질문은 지표에서 제외. 누락된 테스트 근거를 임의로 N/A로 처리하면 안 됨.
strict 모드Noul ≥0.5, Score 최빈 레벨이 최고 레벨, Choice 최빈 적용 옵션의 credit=1.0일 때 개별 통과. 적용 질문이 모두 통과해야 최종 1.
reason답변을 바탕으로 코드가 만드는 설명. 생성형 rationale이나 모델 사고 과정이 아님.
strict는 확률 100%를 요구하는 모드가 아니다
strict의 이진 규칙과 안전 임계값은 구분한다. 전부 N/A이면 score=1이므로 적용 질문 수가 0인 경우 별도 보류한다. high-risk 관문을 DeepEval 기본 threshold나 평균 점수에 위임하지 않는다. [S8]

Confidence: 확률·척도·정답률은 다르다

타입의미 / 공식
Noulp = P(true). 별도 confidence 필드는 없다. 필요 시 abs(2p−1)를 derived 값으로 별도 저장하며 이것을 긍정 확률과 혼동하지 않는다.
ChoiceC = (p_max − 1/n) / (1 − 1/n). 최고 확률만 보므로 나머지 분포의 모양은 구분하지 못한다. n=1에서는 식이 정의되지 않는다.
Scorescore = Σ(i × p_i). 최빈값이 아니라 루브릭 위치의 기대값이며 범위는 0..n−1이다.
Score confidencem=argmax(p_i), D=Σ|i−(n−1)/2| / n. C=max(0, 1−Σp_i|i−m| / D). 기대점수가 아닌 최빈 레벨과의 거리다.

문서 분포 (0, 0.57, 0.43)의 산식 검산은 score=1.43, confidence=0.355다. 실제 API 응답을 받은 결과가 아니라 로컬 산술 확인이다.
